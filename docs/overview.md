# Общее описание решения

`numtheory` это небольшая библиотека на Python с функциями теории чисел: простые числа, делимость, модульная арифметика и последовательности. Сторонние пакеты не нужны, достаточно Python 3.9 или новее.

## Модули

| Модуль | Функции | Назначение |
|---|---|---|
| `primes.py` | `is_prime`, `primes_up_to`, `factorize` | простые числа |
| `divisors.py` | `gcd`, `lcm`, `divisors`, `is_perfect`, `euler_phi` | делимость |
| `modular.py` | `extended_gcd`, `mod_inverse`, `solve_diophantine`, `crt` | модульная арифметика |
| `sequences.py` | `fibonacci`, `fibonacci_list`, `factorial` | последовательности |
| `_validation.py` | `ints_only`, `check_int`, `check_int_list` | внутренняя проверка аргументов |

Файл `__init__.py` пустой. Он нужен, чтобы Python считал папку `numtheory` пакетом и функции можно было импортировать так: `from numtheory.primes import is_prime`.

Подробное описание каждой функции с примерами лежит в [functions.md](functions.md).

## Как устроено решение

**Проверка аргументов.** Каждая функция библиотеки снабжена декоратором `ints_only` из модуля `_validation.py`. Он читает аннотации функции через `inspect.signature` и перед вызовом проверяет каждый аргумент, помеченный как `int`: если это не целое число, выбрасывается `TypeError`. Аргумент с аннотацией `list[int]` (его принимает `crt`) должен быть списком или кортежем, и каждый элемент проверяется отдельно, а в тексте ошибки указан его номер, например `remainders[1]`. Значения `True` и `False` отклоняются везде: в Python `bool` считается подвидом `int`, но числом по смыслу не является. Так тип записывается один раз, в аннотации, а не дважды (в аннотации и в вызове проверки). Для поддержки Python 3.9 список определяется через `typing.get_origin` и `typing.get_args`, а в модулях нельзя писать `from __future__ import annotations`: аннотации превратятся в строки, и декоратор их не увидит. Функции `check_int` и `check_int_list` внутренние помощники декоратора. Подчеркивание в имени модуля означает, что он внутренний и пользователю библиотеки вызывать его не нужно.

**Граничные значения** обрабатываются так, как принято в математике:

- если ответ существует, функция его возвращает: `factorize(-12)` даёт `[-1, 2, 2, 3]`, а `fibonacci(-4)` даёт `-3`;
- если ответа нет, выбрасывается `ValueError`: факториал отрицательного числа, разложение нуля, делители нуля, число без обратного по модулю, диофантово уравнение без целых решений, несовместная система сравнений.

**Связи между функциями.** Все модули используют общий `_validation.py`. Других связей между модулями две: `euler_phi` из `divisors` вызывает `factorize` из `primes`, а `modular` ни от `primes`, ни от `divisors` не зависит. Внутри модуля `divisors` функция `lcm` вызывает `gcd`, а `is_perfect` вызывает `divisors`. Внутри модуля `modular` `mod_inverse` и `solve_diophantine` вызывают `extended_gcd`, а `crt` вызывает `extended_gcd` и `mod_inverse`.

## Алгоритмы

| Функция | Алгоритм | Сложность |
|---|---|---|
| `is_prime` | перебор делителей до √n | O(√n) |
| `primes_up_to` | решето Эратосфена | O(n log log n) |
| `factorize` | деление на наименьший делитель | O(√n) |
| `gcd` | алгоритм Евклида | O(log n) |
| `lcm` | через НОД | O(log n) |
| `divisors` | перебор делителей до √n | O(√n) |
| `is_perfect` | сумма делителей | O(√n) |
| `euler_phi` | формула по простым множителям из `factorize` | O(√n) |
| `extended_gcd` | расширенный алгоритм Евклида | O(log n) |
| `mod_inverse` | через `extended_gcd` | O(log m) |
| `solve_diophantine` | через `extended_gcd` и сдвиг частного решения | O(log n) |
| `crt` | последовательное объединение сравнений | O(k · log M) |
| `fibonacci` | цикл | O(n) |
| `fibonacci_list` | цикл | O(n) |
| `factorial` | цикл | O(n) |

В таблице `n` это абсолютная величина аргумента (для двух аргументов большая из них), `m` это модуль, `k` это количество сравнений в `crt`, а `M` это НОК модулей. Оценка для `crt` не учитывает рост чисел при умножении.

Вычисления идут в циклах, поэтому большие аргументы вроде `fibonacci(5000)` или `factorial(5000)` не упираются в ограничение глубины рекурсии Python. Рекурсия есть только в одном месте: для отрицательного номера `fibonacci` один раз вызывает сама себя с положительным номером.
