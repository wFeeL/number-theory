# Общее описание решения

`numtheory` это небольшая библиотека на Python с функциями теории чисел: простые числа, делимость и последовательности. Сторонние пакеты не нужны, достаточно Python 3.9 или новее.

## Структура проекта

```text
number-theory/
├── README.md
├── .gitignore
├── numtheory/
│   ├── __init__.py
│   ├── _validation.py
│   ├── primes.py
│   ├── divisors.py
│   └── sequences.py
└── docs/
    ├── overview.md
    ├── functions.md
    └── changelog.md
```

## Модули

| Модуль | Функции | Назначение |
|---|---|---|
| `primes.py` | `is_prime`, `primes_up_to`, `factorize` | простые числа |
| `divisors.py` | `gcd`, `lcm`, `divisors`, `is_perfect` | делимость |
| `sequences.py` | `fibonacci`, `fibonacci_list`, `factorial` | последовательности |
| `_validation.py` | `check_int` | внутренняя проверка аргументов |

Файл `__init__.py` пустой. Он нужен, чтобы Python считал папку `numtheory` пакетом и функции можно было импортировать так: `from numtheory.primes import is_prime`.

Подробное описание каждой функции с примерами лежит в [functions.md](functions.md).

## Как устроено решение

**Проверка аргументов.** Каждая функция первым делом вызывает `check_int` из модуля `_validation.py`. Если аргумент не целое число, выбрасывается `TypeError`. Значения `True` и `False` тоже отклоняются: в Python `bool` считается подвидом `int`, но числом по смыслу не является. Подчёркивание в имени модуля означает, что он внутренний и пользователю библиотеки вызывать его не нужно.

**Граничные значения** обрабатываются так, как принято в математике:

- если ответ существует, функция его возвращает: `factorize(-12)` даёт `[-1, 2, 2, 3]`, а `fibonacci(-4)` даёт `-3`;
- если ответа нет, выбрасывается `ValueError`: факториал отрицательного числа, разложение нуля, делители нуля.

**Связи между функциями.** Модули друг от друга не зависят, кроме общего `_validation.py`. Внутри модуля `divisors` функция `lcm` вызывает `gcd`, а `is_perfect` вызывает `divisors`.

## Алгоритмы

| Функция | Алгоритм | Сложность |
|---|---|---|
| `is_prime` | перебор делителей до √n | O(√n) |
| `primes_up_to` | решето Эратосфена | O(n log log n) |
| `factorize` | деление на наименьший делитель | O(√n) |
| `gcd` | алгоритм Евклида | O(log n) |
| `lcm` | через НОД | O(log n) |
| `divisors` | перебор делителей до √n | O(√n) |
| `is_perfect` | сумма делителей | O(√n) |
| `fibonacci` | цикл | O(n) |
| `fibonacci_list` | цикл | O(n) |
| `factorial` | цикл | O(n) |

Вычисления идут в циклах, поэтому большие аргументы вроде `fibonacci(5000)` или `factorial(5000)` не упираются в ограничение глубины рекурсии Python. Рекурсия есть только в одном месте: для отрицательного номера `fibonacci` один раз вызывает сама себя с положительным номером.
